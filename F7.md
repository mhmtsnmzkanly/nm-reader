# Framework7 v9 Core Mobile UI Spec (NMR)

## Summary
This document defines the **mobile-first** Framework7 v9 Core interface that mirrors the current web site's functional flow. The target is a **fully functional** mobile app (web at `/mobile`) that can also be packaged via **Capacitor** for Android/iOS stores.

**Note:** The project is reorganized under a top-level `ui` folder:
- Existing Tailwind/package/web assets live in `ui/web` (current web UI project).
- The Framework7 app source lives in `ui/mobile` and builds into `public/mobile`.

## Goals
- Provide the **same end‑to‑end user experience** as the current web site (browse → content → chapters → reader → login → wallet → unlock).
- Use **Framework7 v9 Core** (Vanilla JS + HTML/CSS).
- Keep a **single codebase** that serves `/mobile` on the web and builds **native bundles** with Capacitor.

## Non‑Goals (Out of Scope)
- Admin panel.
- Payment provider integration (packages remain informational).

---

## 1) App Entry & Architecture

### Web Entry
- Path: `/mobile`
- Entry file: `public/mobile/index.html`
- Assets: Vite outputs hashed JS/CSS under `public/mobile/assets`.
- Server route should serve `index.html` for `/mobile` and `/mobile/*` so Framework7 routing works.
### Build Output
- Source: `ui/mobile`
- Dist: `public/mobile`

### Native (Capacitor)
- Same web build served inside Capacitor WebView.
- `API_BASE_URL` env for native builds (e.g. `https://example.com/api/v1`).
- Web builds use relative `/api/v1`.

### Auth Strategy
- **Primary**: session cookie + CSRF (when running on web).
- **Fallback**: `Authorization: Bearer <api_token>` for native.
- Login response already returns `api_token`; store in local storage and use in API client for native builds.

## 3) API Usage (API_REFERENCE.md as source of truth)

### Browse
- `GET /content/type/{type}`
- `GET /latest-chapters`

### Content
- `GET /content/{type}/{slug}`
- `GET /content/{type}/{slug}/chapters`

### Reader
- `GET /content/{type}/{slug}/chapter/{chapterNumber}`

### Unlock
- `POST /chapter/{chapterId}/unlock`
- Optional: `POST /content/{type}/{slug}/unlock`

### Wallet
- `GET /user/wallet`
- `GET /user/wallet/transactions`

### Social (P1)
- `POST /content/{type}/{slug}/follow`
- `DELETE /content/{type}/{slug}/follow`
- `POST /content/{type}/{slug}/rate`
- `GET /content/{type}/{slug}/comments`
- `POST /content/{type}/{slug}/comment`
- `GET /chapter/{chapterId}/comments`
- `POST /chapter/{chapterId}/comment`

## 4) UI/UX Rules

### Lock State (Chapter Cards)
- Use `access` info in chapter payload:
  - `chapter_unlock_price`
  - `is_chapter_unlocked`
  - `is_series_unlocked`
- If locked:
  - Show lock badge with coin price
  - Tap triggers purchase modal
- If unlocked:
  - Tap opens reader

### Purchase Flow
- Modal shows price and confirmation.
- On success:
  - Update wallet balance in UI
  - Update chapter state to unlocked
  - Navigate to reader

### Reader
- Text: markdown/plain rendering + font size control (P1)
- Image: vertical list with lazy loading

### Error Handling
- Use toast/snackbar with API error.message.
- On 401: open login modal.
