# NovelMangaReader Database Documentation

This document provides a comprehensive technical overview of the Database Schema for the NM Reader project.

---

## 1. Architectural Overview

- **Engine**: MySQL / MariaDB (InnoDB)
- **Charset**: `utf8mb4_unicode_ci`
- **ID Strategy**:
    - **Alphanumeric IDs**: Primary entities (`users`, `series`, `chapters`) use random 6 or 8 character alphanumeric strings (e.g., `abc123`). This prevents ID guessing and improves security.
    - **Auto-increment**: Auxiliary and log tables use standard `BIGINT UNSIGNED` auto-incrementing IDs.
- **Relational Integrity**: Strict Foreign Key constraints are used to ensure data consistency.

---

## 2. Entity Relationship Map (Core)

```text
[users] (8 chars ID)
  │
  ├──< [blogs] (6 chars ID)
  ├──< [social_comments] (Self-referencing parent_id)
  ├──< [user_activity] (Tracking)
  ├──< [user_sessions]
  └──< [system_uploads] (Asset tracking)

[series] (6 chars ID)
  │
  ├──< [chapters] (6 chars ID)
  ├──< [series_metadata] (One-to-one)
  ├──< [series_genre_map] >── [series_genres]
  ├──< [series_tag_map]   >── [series_tags]
  ├──< [ratings]
  └──< [user_series_follows]
```

## 3. Detailed Table Breakdown

### 3.1 Core Identity & Content

#### `users`
Central identity storage.
- `id` (char 8): Random unique identifier.
- `roles` (varchar 255): CSV of role IDs (e.g., "1,2"). Default: "4" (User).
- `api_token`: Persistent token for mobile/API access.

#### `series`
Master table for Novels and Manga.
- `id` (char 6): Random identifier.
- `type`: ENUM (`manga`, `novel`, etc.).
- `chapter_count`, `rating_avg`: Denormalized fields for high-performance listing.

#### `chapters`
The actual reading content.
- `id` (char 6): Random identifier.
- `data` (longtext): Contains either the Markdown body (Novel) or pipe-separated URLs (Manga).
- `created_by` (char 8): Linked to `users.id` (Uploader).

### 3.2 Taxonomy & Metadata

#### `series_metadata`
Detailed info linked to a series (Author, Artist, release year).

#### `series_genres` & `series_tags`
Configurable categorization.
- `ui_config` (JSON): Stores icon names (`bi-fire`) or theme colors (`success`, `danger`) for the frontend.

### 3.3 Social & Interaction

#### `social_comments`
Unified comment system for chapters, blogs, and series.
- Supports threaded replies via `parent_id`.
- Denormalized `upvote_count` and `downvote_count`.

#### `ratings`
Stores user scores (1-5) for series.

#### `user_series_follows`
Many-to-many mapping for the library/bookmark system.

#### `user_notifications`
Centralized notification system for user-to-user and system-to-user alerts.
- `type`: Category of notification (`follow`, `upvote`, `system`).
- `actor_user_id`: The user who triggered the notification (optional).
- `is_read`: Boolean flag for read/unread status.
- `data` (JSON): Context-specific metadata (e.g., links, IDs).

## 4. Tracking & Analytics

#### `analytics_events` (Buffer Table)
Logs every view, search, and click. This table is intended to be high-volume and periodically cleared.

#### `analytics_snapshots_*`
Summarized data generated by the `analytics_aggregate.php` script.
- `daily`: General KPIs (views, funnel).
- `series_top`: Most viewed series per day.
- `health`: Server performance and error rates.

#### `system_uploads`
Persistent log of every image uploaded to the server.
- `file_path`: Relative URL to the asset (e.g., `/uploads/chapter.abc.jpg`).
- Tracks file size and MIME type for auditing.

---

## 5. Security & Logs

#### `admin_actions`
Audit trail for every moderator action (delete, ban, update).
- `target_type`: The entity being moderated (`chapter`, `user`, etc.).

#### `system_audit_logs`
HTTP-level access logs including duration (ms) and IP hashes.

#### `user_sessions` & `user_refresh_tokens`
Secure session management with expiration and revocation support.

---

## 6. Maintenance Commands

To keep the database healthy and analytics up to date:

- **Aggregate Stats**: `php app/Console/analytics_aggregate.php`
- **Cleanup Logs**: `php app/Console/retention_cleanup.php`
- **Backup**: `php app/Console/system_backup.php`
